title: Reading results
description: What each rule id from the Usuba Checker Scripts means, and what a warning means instead of a failure.
---

Every problem the Checker Scripts report carries a **rule id** from [Usuba Standard v0.2](/docs/standard/), a plain reason and a
fix hint.

## Problems and warnings

| Kind | How it shows | Meaning |
|------|--------------|---------|
| Problem | `  [USB-B05] …  Fix: …` under `FAIL` | The plugin does not work, or reports something that isn't true. |
| Warning | `  warn …` | Something risky the plugin may legitimately need. It never fails a plugin; review it. |

Only clearly destructive commands fail outright (`USB-S03`). Deleting your home folder is a failure. Writing outside the plugin's
own directory is a warning.

## Rule ids

Every rule id is `USB-<family><number>`. A few that come up often:

| Rule id | Reason |
|---------|--------|
| `USB-B05` | Runs a program that isn't on a stock Omarchy install and isn't shipped with the plugin. |
| `USB-A04` | Calls a method that doesn't exist on that object, like `start()` on a Quickshell `Process`. |
| `USB-H02` | Shows a hardcoded reading as if it were live data. |
| `USB-B02` | Calls an X11-only tool on a Wayland desktop. |
| `USB-S01` | Writes outside the plugin's own directory. Flagged for review. |

The full list, with the level of every rule, is [Usuba Standard v0.2](/docs/standard/).

## A failing panel

A plugin can pass every static check and still be wrong: it loads, and the panel shows nothing. Static checks cannot catch that, so
on the reference build the Checker Scripts also run a runtime probe — they boot the real Omarchy shell, load the plugin, and watch
whether anything visible draws.

Even that isn't the whole story. On the Dell sweep, 137 plugins passed the scripts and still had problems that only showed up in
use, like a toggle that opens nothing. That gap is what the [Usuba Checker Model](/docs/model/) is being trained to close.
