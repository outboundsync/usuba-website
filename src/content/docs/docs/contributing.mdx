## How to help

1. **Report a plugin the Checker Scripts get wrong.** A false pass or a false fail against real Omarchy hardware is the most useful
   bug report we get, especially a plugin that loads fine and breaks in use.
   [Open an issue](https://github.com/outboundsync/usuba-checker-scripts/issues).
2. **Propose a rule.** The standard is the Checker Scripts' contract; a new rule needs a reason, a failing example and a fix.
3. **Help the model.** Labelled in-use bugs and false alarms from real plugins, reports of where the model and the scripts disagree
   with your machine, and evaluation time for the next run. [Open an issue](https://github.com/outboundsync/usuba-checker-models/issues).
4. **Omarchy maintainers:** tell us when a release will change what "working" means, and review the rules against your intent for
   the plugin contract.

Feedback and changes are welcome as GitHub issues or pull requests. We are not asking for donations.

## Style

Plain and honest. Say what it does, what is done and what is not. Status is always visible. Numbers carry their context:
what was tested, out of how many, and whether the result is preliminary.
