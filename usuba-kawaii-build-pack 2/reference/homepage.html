AI is bad at Omarchy plugins

We gave 49 real plugin requests to the top models and ran every answer in real Omarchy 4.0.4.

What goes wrong

  • Made-up APIs

    Calls to functions and commands that Omarchy doesn't have.

  • Fake data dressed up as real

    A Dropbox widget showing storage numbers with Dropbox not even installed.

  • Panels that show nothing

    The plugin loads, and the panel is empty.

  • X11-only tools

    Tools that don't exist on Omarchy, so the plugin can't run.

Usuba Checker Available now

An open test, not a model. It checks whether an Omarchy plugin actually works, and tells you how to fix it.

  • Reads the code

    Flags invented APIs, missing helper scripts, made-up command flags and fake data.

  • Runs it for real

    Loads the plugin in a real Omarchy shell and catches load errors and crashes.

  • Explains every problem

    Each one comes with a rule id, a plain reason and a fix hint.

  • Warns before it fails

    Risky commands a plugin may need are warnings. Only clearly destructive ones, like deleting your home folder, fail.

  • Follows a public standard

    The rules are written up as an open standard for what a working Omarchy plugin is.

  • Matches real hardware

    It agrees with a laptop running Omarchy on all 90 plugins in our answer key.

$ usuba check ./dropbox-widget
✗ fake-data   Shows storage numbers, but Dropbox isn't installed.
  fix: detect Dropbox first, and show an empty state without it.
✗ x11-only    Calls xdotool, which doesn't exist on Omarchy.
  fix: use hyprctl for window info instead.
⚠ risky-cmd   Deletes ~/.cache/dropbox-widget. Allowed; review it.

2 problems, 1 warning
